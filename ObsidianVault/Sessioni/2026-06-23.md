## Task #75 — Fix regressione critica "non vedo più dati del corso"

Segnalazione utente: in nessuna schermata si vedevano più dati corso (ore fatte/pianificate, voti) — visibili solo le ore istruttori.

**Root cause**: `PracticalTask.plannedHours` in `reference_models.dart` era `int` con cast rigido (`as int?`). I task id 316/317 del nuovo courseType `maml` (modulo 54, sottomodulo 54.1, dato ufficiale `BTC VFI AVES.pdf`, integrato task #64-65 di questa stessa sessione) hanno ore ufficiali frazionarie legittime: **1.5h** ciascuno (verificato: somma task 54.1 = 15h = `practicalHours` del sottomodulo, sia prima che dopo il fix, via fetch diretto da GitHub + check Python). Un double JSON (`1.5`) non soddisfa `as int?` — lancia un `TypeError` Dart a runtime, non viene troncato/arrotondato.

**Blast radius**: `ReferenceService.getCourseTypes()` fa il parsing di **tutti e 6** i courseTypes in un'unica chiamata `.map()` senza isolamento per-item/try-catch. L'eccezione su `maml` (modulo 54.1) propagava e falliva l'intera chiamata, rompendo quasi ogni schermata che dipende da `getCourseTypes()` (overview, calendario, presenze, voti, dettaglio corso). Le schermate ore-istruttori (`GradeService.getUpdatesForInstructor`, `getTeachingHoursRollingYear`, `getProfessionalUpdateHoursLast2Years`) leggono `updates.json`/`schedules.json` direttamente, senza passare da `getCourseTypes()` — da qui il sintomo esatto riportato: "vedo solo ore istruttori".

**Fix**: propagato `double` per `plannedHours` (invece di arrotondare/troncare, per non corrompere il dato ufficiale frazionario verificato) in 3 file:
- `reference_models.dart`: `PracticalTask.plannedHours` → `double`, parsing con `(j['plannedHours'] as num?)?.toDouble() ?? 0`.
- `course_types_tab.dart` (editor admin task pratici): `keyboardType` decimale, parsing `double.tryParse` con gestione virgola, nuovo helper `_fmtNum` per evitare ".0" superfluo in UI mantenendo i decimali reali (es. "1.5" resta "1.5", "3.0" mostra "3").
- `schedule_tab.dart` (dropdown selezione task pratica in dialog pianificazione lezione): map `taskRemaining` da `<dynamic, int>` a `<dynamic, num>` (necessario perché `num.clamp()` ritorna `num`, non il sottotipo originale, una volta che l'operando è `double`), stesso pattern `_fmtNum` locale.

`schedule_service.dart` non ha richiesto modifiche: i confronti `int`/`double` (entrambi `num`) funzionano nativamente senza cast.

**Verifica**: `flutter analyze` → 155 issue totali, tutte lint preesistenti non correlate (deprecazioni, unused import in altri file), zero errori di compilazione nei 3 file toccati e nel progetto. `flutter build web --release` → successo (83.8s). Dato live riverificato fresco da GitHub (`gh api .../reference.json`): task 316/317 confermati `plannedHours: 1.5` come double JSON, identico alla diagnosi originale.
